# AI-RAN 架构与平台（2026）

> **更新：2026-05** | 来源：NVIDIA Developer、Nokia MWC 2026、GTC 2026

## 1. AI-RAN 硬件革命

### 从 ASIC/FPGA 到 GPU：为什么转变？

传统基带处理依赖定制 ASIC 或 FPGA。转向 GPU 处理的驱动力：

1. **灵活性**：GPU 可以在同一硅片上运行基带（5G NR PHY/MAC）和 AI 工作负载
2. **AI 原生**：GPU 是 ML 推理和训练的原生平台
3. **软件定义**：CUDA 生态支持快速算法更新，而无需重新设计硬件
4. **经济性**：共享基础设施降低总拥有成本

## 2. NVIDIA ARC 平台家族

### NVIDIA ARC（Aerial RAN Computer）

用于高容量基站的全尺寸平台：

| 组件 | 规格 | 用途 |
|:---|:---|:---|
| **CPU** | NVIDIA Grace（ARM v9，72 核） | 控制面、OS、容器运行时 |
| **GPU** | L40S / H100 级 | 基带处理 + AI 推理 |
| **DPU** | BlueField-3 | 网络卸载、安全、存储 |
| **功耗** | 300-500W | 多扇区宏基站 |
| **形态** | 2U 机架式 | 标准电信机架 |
| **5G 容量** | 最高 100 MHz × 4 扇区 | 高容量城市场景 |

### NVIDIA ARC-Compact

用于典型基站的功耗优化平台：

| 组件 | 规格 | 用途 |
|:---|:---|:---|
| **CPU** | NVIDIA Grace（ARM v9） | 控制面、编排 |
| **GPU** | L4（72W TDP） | 基带 + 边缘 AI 推理 |
| **功耗** | 72W GPU + 约 150W 总计 | 符合基站功耗预算 |
| **形态** | 紧凑/加固型 | 户外机柜、路灯杆 |
| **5G 容量** | 最高 40 MHz × 3 扇区 | 标准郊区/农村 |

**K8S 工程师的关键洞察**：ARC-Compact 的 72W L4 GPU 专为典型的 300W 基站功耗包络设计，同时为 AI 工作负载留有余量。

### 对比：传统 vs. AI-RAN 硬件

| 维度 | 传统 RAN | AI-RAN（NVIDIA ARC） |
|:---|:---|:---|
| **处理器** | 定制 ASIC / FPGA | NVIDIA GPU + Grace CPU |
| **基带** | 固定功能硬件 | 软件定义（CUDA） |
| **AI 能力** | 无或外部 | 原生（片上） |
| **升级路径** | 硬件更换 | 软件更新 |
| **边缘 AI 收入** | 不可能 | GPU 与 B2B AI 共享 |
| **功耗** | 200-500W | 150-500W（可比） |
| **厂商锁定** | 高（专有） | 低（开放 CUDA API） |

## 3. GPU 加速基带：NVIDIA Aerial SDK

### 架构

```
┌─────────────────────────────────────────┐
│          Aerial Framework                │
│  ┌──────────────────────────────────┐   │
│  │      5G NR 协议栈                 │   │
│  │  ┌─────┐ ┌─────┐ ┌─────┐       │   │
│  │  │ L3  │ │ L2  │ │ L1  │       │   │
│  │  │RRC/ │ │MAC/ │ │PHY  │       │   │
│  │  │PDCP │ │RLC  │ │     │       │   │
│  │  └─────┘ └─────┘ └─────┘       │   │
│  └──────────────────────────────────┘   │
│                                          │
│  ┌──────────────────────────────────┐   │
│  │      GPU 加速库                   │   │
│  │  ┌────────┐ ┌────────┐          │   │
│  │  │ cuMAC  │ │ cuPHY  │          │   │
│  │  │调度器  │ │信号    │          │   │
│  │  │        │ │处理    │          │   │
│  │  └────────┘ └────────┘          │   │

│                                          │

│  │  └────────┘ └────────┘          │   │
│  └──────────────────────────────────┘   │
└─────────────────────────────────────────┘
```

### cuMAC：GPU 加速的 MAC 调度器
- **功能**：基带中用于资源分配和调度的 L2 调度器
- **性能**：亚毫秒调度决策，支持数百个 UE
- **AI 集成**：ML 模型可直接嵌入调度循环
- **开源**：可在 [GitHub: NVIDIA/aerial-cuda-accelerated-ran](https://github.com/NVIDIA/aerial-cuda-accelerated-ran) 获取

### cuPHY：GPU 加速的物理层
- **功能**：5G NR 物理层处理（FFT/IFFT、信道编码、调制）
- **性能**：在 L4 GPU 上实时处理标准载波配置
- **灵活性**：通过 CUDA 代码更改进行算法更新（无需重新设计硬件）

### pyAerial：Python API 绑定
- **目的**：支持基于 Python 的 RAN 算法开发
- **用例**：快速原型设计 ML 增强的基带算法
- **集成**：直接连接 PyTorch/TensorFlow 用于 ML 管线

### GPU 资源分区（AI-with-RAN）

2026 年的关键创新是 **RAN 和 AI 之间的动态 GPU 资源共享**：

```
时间：  ┌──────────────────────────────────────────────┐
        │  流量高峰（08:00-20:00）                       │
GPU：   │  [████████ RAN 80% ████] [██ AI 20% ██]      │
        │                                               │
        │  流量低谷（20:00-08:00）                       │
GPU：   │  [████ RAN 30% ████] [████████ AI 70% ████████]│
        └──────────────────────────────────────────────┘
```

- **优先级**：RAN 始终获得保证的最小资源
- **弹性**：AI 工作负载动态使用可用 GPU 容量
- **隔离**：硬件级隔离确保 RAN 延迟 SLO 达标
- **收入**：低谷期 AI 推理服务 B2B 客户（如智慧城市、自动驾驶）

## 6. 边缘计算集成模式

### 模式 1：共置 AI + RAN（AI-with-RAN）
```
基站侧 NVIDIA ARC
├── RAN：cuMAC + cuPHY（基带）
├── AI：推理引擎（TensorRT）
└── 共享：GPU 内存、NVLink 带宽
```
**优点**：最低延迟、最高效率
**缺点**：资源管理复杂、RAN 优先约束

### 模式 2：相邻 AI 集群（AI-on-RAN）
```
基站机架
├── NVIDIA ARC（仅 RAN）
├── 独立 GPU 服务器（仅 AI）
└── 连接：25GbE / NVLink 桥接
```
**优点**：管理简单、独立扩展
**缺点**：AI-RAN 交互延迟更高、硬件更多

### 模式 3：区域边缘 AI（AI-for-RAN）
```
区域边缘数据中心
├── Near-RT RIC（xApps + ML 推理）
├── AI 训练集群（GPU）
└── 通过 E2 接口连接到基站
```
**优点**：集中管理、完整 GPU 算力用于训练
**缺点**：更高延迟（10ms-1s），仅限 Non-RT/Near-RT 用例

## 7. K8S 工程 AI-RAN 注意事项

### K8S 上的 GPU 调度
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: ai-ran-workload
spec:
  containers:
  - name: baseband
    image: nvidia/aerial-cuMAC:latest
    resources:
      limits:
        nvidia.com/gpu: 1
        nvidia.com/mig-1g.10gb: 1  # 基带的 MIG 分区
  - name: ai-inference
    image: custom/edge-ai:latest
    resources:
      limits:
        nvidia.com/mig-1g.10gb: 1  # AI 的 MIG 分区
```

### 关键挑战
1. **实时保证**：基带处理必须满足严格的时序 SLO
2. **GPU 分区**：NVIDIA MIG（多实例 GPU）用于工作负载隔离
3. **网络拓扑**：多网络接口 Pod（管理、前传、中传）
4. **功耗管理**：GPU 功耗封顶以符合基站预算
5. **散热管理**：户外部署的加固外壳

### 推荐的 AI-RAN K8S 栈
- **运行时**：Containerd + NVIDIA Container Toolkit
- **CNI**：Multus CNI + SR-IOV 用于前传
- **GPU**：NVIDIA GPU Operator + MIG Manager
- **调度**：带实时感知的自定义调度器
- **可观测性**：DCGM Exporter + Prometheus + Grafana
