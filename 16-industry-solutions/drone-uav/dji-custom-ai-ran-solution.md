## 1. DJI 产品生态与通信现状

### 1.1 主要产品线

| 产品线 | 代表型号 | 通信方式 | AI-RAN 机会 |
|:---|:---|:---|:---|
| 行业旗舰 | Matrice M350 RTK | O4 图传（20km）+ 可选 4G 模块 | ⭐⭐⭐⭐ |
| 中型行业机 | Matrice M30/M30T | O3 图传 + Cellular 模块 | ⭐⭐⭐⭐⭐ |
| 机场系统 | DJI Dock 2 / Dock | 远程调度 + 4G/5G 回传 | ⭐⭐⭐⭐⭐ |
| 农业植保 | Agras T60/T25 | 图传 + RTK | ⭐⭐⭐ |
| 轻量行业机 | Mini/Mavic 行业版 | OcuSync + 4G 增强 | ⭐⭐⭐ |
| 消费级 | Mavic/Air/Mini | OcuSync 私有链路 | ⭐⭐（监管场景） |

### 1.2 现有通信能力盘点

- **私有图传**：OcuSync/O3/O4 系列，2.4/5.8GHz，C2 + 视频一体，距离 5-20km
- **DJI Cellular 模块**：4G（TD-LTE）图传增强模块，实现图传超距增强、网络 RTK、联网服务
- **5G 网联生态**：DJI Enterprise 生态合作方案，如中国移动"哈勃一号"机载 5G 终端、"天宇云盒 M2"（适配 M30 + 机场），用 5G 蜂窝网替代自建链路
- **DJI Cloud API**：云端开放接口，支持第三方平台接入无人机遥测、直播、航线管理
- **Payload SDK / PSDK**：机载负载开发接口，可挂载自研 5G/AI 负载

### 1.3 关键洞察

**DJI 自身不做基站/RAN**，其 5G 能力依赖：
1. 机载 5G 模组（第三方生态合作，如运营商定制终端）
2. 云端平台对接（DJI Cloud API / FlightHub 2）

**这就是创业公司/集成商的机会窗口**：DJI 提供飞机与 API，**网络侧的 AI-RAN 优化是空白地带**。

## 2. DJI 场景的 AI-RAN 需求分析

### 2.1 典型场景痛点

| 场景 | 痛点 | AI-RAN 可解决方式 |
|:---|:---|:---|
| 电力巡检（机场） | 山区信号弱、图传卡顿 | 低空覆盖优化 xApp + 链路质量预测 |
| 城市安防巡逻 | 楼宇遮挡、多机并发 | 干扰协调 + 切片保障 |
| 应急消防 | 现场无网络覆盖 | 无人机挂载便携 O-RU 快速建网 |
| 农业植保集群 | 农忙高峰多机并发、偏远弱网 | 容量预测 + 临时增强覆盖 |
| 物流常态化航线 | 全天候、跨区切换频繁 | 航路感知的切换优化 |
| 灯光秀编队 | 千架级同步控制 | MBS 组播 + 编队调度 xApp |

## 3. 核心方案一：5G 网联化增强

### 3.1 方案概述

为 DJI 机场/行业机提供"网络侧"的 5G 接入优化，让 DJI Cloud API 的远程作业更稳定。

### 3.2 架构

```
DJI Dock 2（机场）──DJI Cloud API──► 客户云平台
     │
     │ 4G/5G 回传（机载终端：哈勃一号/天宇云盒类）
     ▼
┌────────────────────────────────────┐
│  AI-RAN 优化层（我方提供）          │
│  ├── 低空覆盖规划与优化             │
│  ├── AerialHandoverXApp（切换优化） │
│  ├── UAVSliceXApp（视频切片保障）   │
│  └── 链路质量监测与自愈             │
└────────────────────────────────────┘
```

### 3.3 交付物

1. **航线网络勘测报告**：沿巡检航线的 5G 覆盖/质量实测与优化建议
2. **xApp 部署包**：部署于运营商/专网 RIC，针对客户航线定制
3. **链路 SLA 监控平台**：端到端时延/丢包/切换成功率仪表盘

### 3.4 客户与付费方

- 电网/管道/铁路业主（专网自建或购买运营商切片）
- 运营商（政企行业包：5G+无人机巡检套餐）

## 4. 核心方案二：机场（Dock）无人值守 AI 网络

### 4.1 方案概述

围绕 DJI Dock 2 的"无人值守作业"，打造**机场边缘节点 = 网络 + 算力 + AI** 三位一体。

### 4.2 机场边缘节点设计

```
┌─────────────── DJI Dock 2 边缘柜 ───────────────┐
│                                                 │
│  ┌──────────┐  ┌──────────┐  ┌──────────────┐   │
│  │ 轻量 O-DU │  │ GPU 推理 │  │ 数据缓存/    │   │
│  │ (专网)   │  │ 节点     │  │ 边缘预处理    │   │
│  │ srsRAN/  │  │ Jetson/  │  │ (航线影像、  │   │
│  │ Aerial   │  │ L4 GPU   │  │  缺陷标注)   │   │
│  └────┬─────┘  └────┬─────┘  └──────┬───────┘   │
│       └─────────────┼───────────────┘           │
│                     │ 本地 MEC 闭环              │
└─────────────────────┼───────────────────────────┘
                      │
        ┌─────────────┴─────────────┐
        ▼                           ▼
   无人机就近接入               缺陷结果 <500ms
   （低时延 C2）                送达客户平台
```

### 4.3 关键特性

- **本地闭环**：无人机优先接入机场本地 O-RU，C2 时延 <20ms，弱公网也能作业
- **就近推理**：巡检视频在机场本地 GPU 完成缺陷检测，仅回传结果与关键帧（带宽省 90%）
- **断网自治**：公网中断时机场可独立执行预置航线任务
- **AI 增值**：按行业加载检测模型（电力：绝缘子破损；光伏：热斑；管道：泄漏）

### 4.4 商业模式

- 边缘柜硬件 + 软件订阅（按机场数量收费）
- AI 检测模型按行业包订阅
- 与 DJI 集成商渠道分成合作

## 5. 核心方案三：边缘 AI 视频分析平台

### 5.1 方案概述

不碰飞机、不碰网络，只做 DJI Cloud API 之上的**视频 AI 中台**——最低门槛切入点。

### 5.2 架构

```
DJI 机队 ──DJI Cloud API/直播流──► 视频 AI 中台（我方）
                                      │
                     ┌────────────────┼────────────────┐
                     ▼                ▼                ▼
               实时目标检测      航线影像比对      报告自动生成
               (TensorRT)     (多期变化检测)    (大模型生成)
                     │                │                │
                     └────────────────┴────────────────┘
                                      ▼
                          客户工单系统/数字孪生平台
```

### 5.3 技术要点

- 对接 DJI Cloud API 的直播（RTMP/GB28181）与媒体文件接口
- GPU 推理集群（云端或边缘），Triton + TensorRT 部署
- 多期影像 AI 比对：同一航线不同时期的缺陷变化自动追踪
- 大模型报告：检测结论自动生成巡检报告（LLM 摘要）

## 6. 核心方案四：编队与集群作业网络

### 6.1 场景

- 千架级灯光秀：统一指令下发同步性要求极高
- 农业植保集群：多机同场作业的防碰撞与调度

### 6.2 方案

- 为活动/农场提供**临时专网**（便携 O-RU + 边缘 O-DU）
- MBS 组播承载统一控制指令，保障毫秒级同步
- SwarmSchedXApp 为编队成员成组预留资源
- AI 航路规划避免多机冲突（与 DJI 地面站 API 对接）

## 8. 与 DJI 的合作模式与切入路径

### 8.1 现实判断

**直接成为 DJI 供应商难度高**：DJI 自研能力极强，通信/算法核心不外求。可行路径按难度排序：

| 路径 | 难度 | 说明 |
|:---|:---|:---|
| **A. 生态合作伙伴** | ⭐⭐⭐ | 申请 DJI Enterprise 生态合作，联合方案认证（参考哈勃一号/天宇云盒模式） |
| **B. 集成商模式** | ⭐⭐ | 不依赖 DJI 官方，采购 DJI 设备 + 自研网络/AI 层，向行业客户交付整体方案 |
| **C. 运营商联合体** | ⭐⭐⭐ | 与运营商合作"5G+无人机"行业包，DJI 飞机作为生态选项之一 |
| **D. 纯网络侧** | ⭐ | 完全绕开 DJI，做低空智联网基础设施（低空经济大盘） |

**建议策略**：B + D 组合——以集成商模式用 DJI 设备快速落地项目，同时沉淀与设备无关的低空网络能力，避免单一厂商依赖。

### 8.2 差异化卖点（对 DJI/客户的价值主张）

1. **网络是 DJI 不做的部分**：飞机再好，弱网照样传不回画面
2. **合规能力**：5G 网联满足民航局监管要求，私有链路做不到
3. **AI 增值**：把"卖飞机"变成"卖巡检结果"，客户按效果付费

## 10. 成本效益分析

### 10.1 单机场项目成本估算（参考）

| 项目 | 成本（人民币） |
|:---|:---|
| DJI Dock 2 + M30T | 15-20 万 |
| 机载 5G 终端 | 0.5-1 万 |
| 机场边缘节点（GPU） | 8-15 万 |
| 专网/切片年费 | 3-8 万/年 |
| AI 模型定制 | 10-30 万（一次性） |
| **合计（首年）** | **约 40-75 万** |

### 10.2 客户收益

- 人工巡检替代：单基杆塔巡检成本降 60-80%
- 缺陷发现时效：从"周级"到"小时级"
- 作业半径：突破遥控器距离限制，单机场覆盖半径 10km+

### 10.3 我方收入模型

- 项目集成费（一次性）：20-40% 毛利
- 软件订阅（机场边缘 + AI 中台）：5-15 万/机场/年
- AI 模型行业包：按检测类型收费

## 11. 风险与挑战

| 风险 | 影响 | 应对 |
|:---|:---|:---|
| DJI 自研补齐网络能力 | 方案被内部化 | 保持多厂商兼容（不止 DJI），绑定运营商与行业客户 |
| 5G 低空覆盖不足 | 体验达不到承诺 | 前期航线勘测必做；专网补盲作为备选 |
| 空域审批周期长 | 项目延期 | 选择已开放低空试点城市先行 |
| DJI 出口管制/供应链风险 | 海外项目受阻 | 国内市场优先，海外用本地化机队 |
| 价格战（集成商众多） | 毛利下降 | 深耕 AI 算法与网络优化壁垒，避免纯硬件倒卖 |
