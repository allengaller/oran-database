## 1. 无人机通信系统概述

### 1.1 传统无人机通信链路

传统消费级/行业无人机主要采用**厂商私有图传协议**（如 DJI OcuSync）：

```
┌─────────────┐    2.4/5.8 GHz 私有链路    ┌─────────────┐
│   遥控器/   │ ◄──────────────────────► │    无人机    │
│   地面站    │   C2 控制 + 实时视频回传   │  (UAV/UE)   │
└─────────────┘   距离限制：5-20 km      └─────────────┘
```

**局限性：**

| 痛点 | 说明 |
|:---|:---|
| 距离受限 | 私有链路受发射功率/视距限制，典型 5-20 km |
| 无法 BVLOS | 超视距（Beyond Visual Line of Sight）作业依赖中继或卫星 |
| 监管困难 | 私有链路无法被监管方（如民航局 UOM）直接感知 |
| 容量瓶颈 | 多机密集作业时频谱干扰严重 |
| 无网络级 QoS | 无法利用蜂窝网络的切片、鉴权、计费能力 |

### 1.2 5G 网联无人机（5G Connected Drones）

3GPP 从 **Release 15** 开始研究蜂窝网络对无人机的支持（TR 36.777 增强 LTE 空中 UE 支持），**Release 16** 正式引入 **UAS（Unmanned Aircraft System）支持**（TS 22.125、UAS NF 网络功能），**Release 17/18** 进一步扩展 **NTN（非地面网络）与空中 UE 增强**。

```
┌─────────────┐         ┌─────────────┐         ┌─────────────┐
│ UAV 控制器  │ ◄─5G──► │   5G 网络    │ ◄─5G──► │  空中 UE    │
│(Pilot/UTM)  │         │ (UAS NF等)  │         │  (无人机)   │
└─────────────┘         └──────┬──────┘         └─────────────┘
                               │
                        ┌──────┴──────┐
                        │  UTM / USS  │  无人机交通管理
                        └─────────────┘
```

**核心优势：**

- **距离突破**：依托蜂窝覆盖，理论上支持任意距离的 BVLOS 作业
- **可信接入**：SIM/eSIM 鉴权，满足监管"看得见、管得住"的要求
- **网络能力开放**：NEF/UTM 接口支持航路规划、地理围栏、动态禁飞区
- **QoS 保障**：5QI 机制为 C2 控制流（高可靠低时延）和视频回传（大带宽）分别保障

### 1.3 低空智联网趋势

中国"低空经济"政策推动下（2024 年写入政府工作报告），**低空智联网**成为 5G-A/6G 的关键场景：

- **通感一体化（ISAC）**：5G-A 基站同时实现通信与雷达感知，探测无合作目标无人机
- **低空覆盖专网**：运营商部署专用低空波束（上倾波束优化）
- **网联化监管**：民航局 UOM 平台与运营商 UTM 对接

## 2. AI-RAN 在无人机通信中的价值

### 2.1 为什么无人机场景特别需要 AI-RAN

空中 UE 与地面 UE 有本质差异，传统静态 RAN 参数无法适应：

| 差异维度 | 地面 UE | 空中 UE（无人机） | AI-RAN 应对 |
|:---|:---|:---|:---|
| 信道环境 | 建筑物遮挡、多径丰富 | 视距为主、干扰暴露面广 | AI 干扰预测与波束自适应 |
| 移动速度 | 0-120 km/h | 0-150 km/h（三维机动） | AI 切换预测、移动性优化 |
| 小区可见数 | 1-3 个 | 高空可见 5-10+ 小区 | AI 干扰协调（ICIC/eICIC 智能化） |
| 业务模式 | 连续流量 | 突发视频+周期遥测+C2 混合 | AI 切片资源动态编排 |
| 密度分布 | 相对均匀 | 航线密集、时空集中 | AI 流量预测与容量调度 |

### 2.2 AI-RAN 三大范式在无人机场景的映射

```
┌─────────────────────────────────────────────────────────┐
│ AI-for-RAN：AI 优化无人机接入的无线网络本身                │
│  ├── 空中 UE 专用切换优化 xApp                            │
│  ├── 低空波束赋形 AI 优化                                 │
│  ├── 无人机流量预测与节能调度                             │
│  └── 干扰检测与协调（AI 识别无人机干扰源）                │
├─────────────────────────────────────────────────────────┤
│ AI-on-RAN：利用 RAN 算力（边缘 GPU）运行无人机 AI 应用     │
│  ├── 无人机视频流实时 AI 分析（缺陷检测/目标识别）          │
│  ├── 低空航路 AI 规划                                     │
│  ├── 无人机编队协同推理（分布式推理）                       │
│  └── 数字孪生低空空域管理                                 │
├─────────────────────────────────────────────────────────┤
│ AI-with-RAN：AI 工作负载与 RAN 共享 GPU 基础设施           │
│  ├── GPU 基带（NVIDIA Aerial）闲时算力调度给无人机推理     │
│  ├── 通感一体数据的 AI 融合处理                            │
│  └── 低空边缘云统一算力池                                 │
└─────────────────────────────────────────────────────────┘
```

### 3.2 关键组件职责

| 组件 | 职责 | 无人机场景定制点 |
|:---|:---|:---|
| **机载 5G 终端** | 无人机接入蜂窝网 | 轻量模组（<50g）、双 SIM 冗余、QoS 感知 |
| **低空专用 O-RU** | 提供上倾波束覆盖 | 3D 波束、通感一体射频、毫米波补充 |

| **Non-RT RIC** | 分钟级以上策略 | 航路流量预测、干扰治理 rApp |
| **边缘 AI 节点** | 视频/感知推理 | 与 O-DU 共址（MEC），GPU 共享 |
| **UTM 对接网关** | 监管与航路管理 | NEF 开放、地理围栏下发 |

## 4. 5G NR 与无人机的集成设计

### 4.1 空中 UE 的 NR 特性适配

| NR 特性 | 无人机适配设计 |
|:---|:---|
| **BWP（带宽部分）** | C2 链路使用窄 BWP 省电；视频回传动态切换宽 BWP |
| **波束管理** | 高空视距场景简化波束扫描，AI 预测最优波束 |
| **URLLC（5QI 82/85）** | C2 控制流使用 1ms 时隙配置 + 预配置授权（CG） |
| **网络切片（S-NSSAI）** | 无人机专用切片：C2 切片 + 视频切片 + 遥测切片 |
| **定位（PRS/RTT）** | 厘米级定位支持精准航线复飞（结合 RTK） |
| **RedCap（Rel-17）** | 轻量级 5G 终端，降低机载模组成本与功耗 |

### 4.2 网络切片设计

```yaml
# 无人机专用切片示例
slices:
  - snssai: {sst: 2, sd: "UAV-C2"}        # C2 控制切片
    qos:
      5qi: 85                                # URLLC
      latency: 10ms
      reliability: 99.999%
    priority: critical
  - snssai: {sst: 2, sd: "UAV-VIDEO"}     # 视频回传切片
    qos:
      5qi: 2                                 #  conversational video
      bandwidth: 20-100 Mbps（4K 多路）
      latency: 100ms
    priority: high
  - snssai: {sst: 2, sd: "UAV-TELEMETRY"} # 遥测/监管切片
    qos:
      5qi: 79
      bandwidth: 低（KB 级周期上报）
    priority: medium
```

### 4.3 低空覆盖设计要点

- **波束上倾**：地面站波束主瓣服务地面，低空覆盖需专用上倾波束或独立扇区
- **站间距**：300-500 米低空飞行时，站间距 1-2 km 可满足连续覆盖
- **毫米波补盲**：城市峡谷航线用 26 GHz 小站提供大带宽热点
- **干扰控制**：高空 UE 可见小区多，需 AI 驱动的跨站干扰协调（见第 9 章）

## 5. 无人机通信的特殊挑战与解决方案

| 挑战 | 机理 | AI-RAN 解决方案 |
|:---|:---|:---|
| **高空干扰暴露** | 空中 UE 无遮挡，同时收到多个小区信号 | AI 干扰图预测 + 协调波束赋形 xApp |
| **频繁切换** | 高空可见小区多，移动导致频繁重选 | 基于轨迹预测的提前切换（LSTM/Transformer） |
| **多普勒频偏** | 150 km/h 高速导致载波频偏 | NR 预补偿 + AI 信道估计增强 |
| **链路闪断** | 建筑物遮挡、姿态变化 | 双链路冗余（5G+私有图传）、AI 链路质量预测 |
| **电量约束** | 机载模组功耗影响航时 | RedCap + DRX 优化 + AI 功耗调度 |
| **监管合规** | 黑飞探测、地理围栏 | 通感一体探测 + UTM 围栏实时下发 |

## 6. 边缘 AI 计算架构

### 6.1 算力部署形态

```
┌────────────────────────────────────────────────────┐
│  机载端（Onboard）     │  实时姿态控制、避障（<10ms） │
│  NVIDIA Jetson Orin    │  轻量模型（<10 TOPS 需求）   │
├────────────────────────────────────────────────────┤
│  机场/起降场（Dock）    │  近距推理、数据缓存          │
│  边缘服务器            │  视频预处理、模型热更新        │
├────────────────────────────────────────────────────┤
│  基站侧 MEC           │  视频 AI 分析、航路规划       │
│  GPU O-DU 共址        │  Aerial 闲时算力复用          │
├────────────────────────────────────────────────────┤
│  区域云/中心云         │  模型训练、数字孪生、大数据分析│
└────────────────────────────────────────────────────┘
```

### 6.2 算力共享机制（AI-with-RAN）

NVIDIA Aerial 平台上，GPU 同时承载基带（cuMAC/cuPHY）与 AI 推理：

- **潮汐调度**：无人机作业高峰（如白天巡检）基带优先；夜间低负荷时释放 GPU 给模型训练
- **CUDA Stream 隔离**：基带处理流与推理流按优先级隔离，保证 TTI 确定性
- **AI-RAN 收益**：单站 GPU 利用率从基带独占的 ~30% 提升至 70%+

### 6.3 典型推理流水线

```
无人机 4K 视频 ──5G切片──► MEC 边缘节点
                              │
                    ┌─────────┴─────────┐
                    ▼                   ▼
              视频解码（NVDEC）    TensorRT 推理
                    │          （缺陷检测/目标识别）
                    ▼                   │
              结果结构化 ──────► 行业应用平台/UTM
                    │
                    └──► 数字孪生体更新
端到端时延目标：< 200 ms
```

## 7. 无人机编队通信与协同控制

### 7.1 编队通信需求

| 场景 | 规模 | 时延要求 | 带宽要求 |
|:---|:---|:---|:---|
| 无人机灯光秀 | 1000+ 架 | <20ms（编队同步） | 低（位置/状态同步） |
| 农业编队喷洒 | 5-20 架 | <50ms | 低 |
| 巡检编队 | 3-10 架 | <100ms | 中（协同视频） |
| 物流配送集群 | 动态数十架 | <100ms | 低 |

### 7.2 AI-RAN 编队支持设计

- **组播/广播（MBS）**：5G NR Multicast-Broadcast Service 为编队下发统一控制指令，避免单播风暴
- **编队专用 xApp**：Near-RT RIC 为编队成员预留成组资源，保障同步时延
- **分布式协同推理**：编队内机间链路（PC5 Sidelink）+ 边缘聚合推理
- **AI 航路协同**：Non-RT RIC rApp 基于全局空域状态为编队生成无冲突四维航迹（4D Trajectory）

### 7.3 PC5 Sidelink 应用

3GPP 定义了 NR Sidelink（PC5 接口），无人机编队可直接机间通信：

- 无需经过基站，机间时延 <10ms
- 用于避障告警、编队内状态同步
- 与 Uu 链路形成双冗余

## 8. 无人机应急通信方案

### 8.1 无人机作为空中基站（UAV-mounted O-RU）

自然灾害（地震、洪涝）导致地面基站损毁时：

```
┌─────────────┐  卫星回传/微波  ┌─────────────┐
│  应急指挥车  │ ◄──────────► │ 高空无人机   │
│  便携 O-DU  │               │ 挂载轻量 O-RU│
│  + O-CU     │               │ 覆盖半径 5km │
└─────────────┘               └──────┬──────┘
                                     │ NR Uu
                              ┌──────┴──────┐
                              │ 受灾区域终端 │
                              └─────────────┘
```

**AI-RAN 增强：**
- Near-RT RIC 应急 xApp：自动识别高话务聚集区，指挥无人机调整悬停位置
- AI 容量预测：基于灾情报送密度预测话务洪峰
- 系留无人机 + 多机接力：延长覆盖时间至 24h+

### 8.2 快速部署流程

| 阶段 | 动作 | 时间目标 |
|:---|:---|:---|
| 1 | 无人机起飞，O-RU 上电自测 | <5 min |
| 2 | O-RU 通过卫星链路对接便携 O-DU（O-FH 接口） | <10 min |
| 3 | SMO 自动配置小区参数，RIC xApp 接管优化 | <15 min |
| 4 | 受灾区域终端接入，优先保障应急号码 | <20 min |

## 9. AI-RAN xApp/rApp 在无人机场景的应用

### 9.1 核心 xApp 清单（Near-RT RIC，10ms-1s 控制环）

| xApp | 功能 | AI 模型 |
|:---|:---|:---|
| **AerialHandoverXApp** | 空中 UE 切换优化 | 轨迹预测（LSTM）+ 强化学习切换决策 |
| **UAVBeamXApp** | 低空波束自适应 | 信道状态预测的波束预对准 |
| **UAVSliceXApp** | 无人机切片资源编排 | DRL 动态资源分配 |
| **SwarmSchedXApp** | 编队成组调度 | 图神经网络（GNN）成员关系建模 |
| **InterferenceXApp** | 跨站干扰协调 | 干扰图预测 + 协调波束赋形 |

### 9.2 核心 rApp 清单（Non-RT RIC，>1s 控制环）

| rApp | 功能 | AI 模型 |
|:---|:---|:---|
| **TrafficForecastRApp** | 低空流量预测（物流高峰、灯光秀） | Transformer 时序预测 |
| **RoutePlanningRApp** | 全域航路规划与冲突消解 | 多智能体强化学习（MARL） |
| **EnergySavingRApp** | 低空小区节能（无航班时休眠上倾波束） | 流量预测驱动休眠决策 |
| **RogueUAVRApp** | 黑飞无人机识别（通感数据融合） | 雷达微多普勒特征分类 |
| **CoverageOptRApp** | 低空覆盖优化（基于航线数据的站址规划） | 覆盖仿真 + 优化算法 |

### 9.3 xApp 开发示例骨架

```python
# AerialHandoverXApp 核心逻辑（基于 xApp Framework）
class AerialHandoverXApp:
    def on_indication(self, e2_msg):
        # 1. 解析 E2 上报的空中 UE 测量报告
        ues = self.extract_aerial_ues(e2_msg)
        for ue in ues:
            # 2. 轨迹预测：基于历史 RSRP 序列预测未来 2s 最优小区
            predicted_best = self.lstm_predictor.predict(
                ue.rsrp_history, ue.trajectory)
            # 3. 决策：预测目标小区负荷（避免乒乓与过载）
            if self.cell_load[predicted_best] < THRESHOLD:
                # 4. 下发 E2 CONTROL：提前切换
                self.send_handover_control(ue, predicted_best)
```

## 10. 安全架构设计

### 10.1 威胁模型

| 威胁 | 目标 | 影响 |
|:---|:---|:---|
| C2 链路劫持 | 夺取无人机控制权 | 灾难性（坠机/被滥用） |
| GPS 欺骗/干扰 | 位置误导 | 偏航、闯入禁区 |
| 视频流窃听 | 敏感区域影像泄露 | 数据安全 |
| 信令洪泛 | 瘫痪低空网络 | 拒绝服务 |
| 黑飞无人机 | 规避监管 | 公共安全风险 |

### 10.2 防护设计

- **接入安全**：5G AKA 双向鉴权 + 无人机专属订阅（UAS NF 与 UTM 联合认证，3GPP TS 23.256）
- **C2 链路保护**：端到端加密（应用层 TLS + NAS/AS 加密双保险），URLLC 切片隔离
- **抗欺骗**：5G NR 定位与 GPS 交叉验证；AI 检测异常轨迹模式
- **监管协同**：遥测切片强制开启，监管方可通过 UTM 获取实时位置（合规前提下的最小化暴露）
- **RIC 安全**：xApp 上架签名审核，E2 接口 TLS 双向认证

### 11.2 AI 优化手段

2. **智能 DRX**：AI 学习飞行任务节奏，定制休眠周期，机载模组功耗降低 30%+
3. **语义压缩**：AI 视频语义编码，相同画质带宽降 40%（AI 编解码在机载端与 MEC 协同）
4. **GPU 基带优化**：cuPHY 对低空大频偏信道的 AI 信道估计，误块率降低 15%
